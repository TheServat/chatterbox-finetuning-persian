# فاین‌تیون Chatterbox برای زبان فارسی

افزودن فارسی به [Chatterbox](https://github.com/resemble-ai/chatterbox) — که فارسی جزو ۲۳ زبان پشتیبانی‌شده‌اش نیست — با مکانیزمی که همیشه بتوان روی آخرین نسخه‌ی پایدار بالادست کار کرد.

---

## شروع سریع

```bash
pip install -r requirements.txt

export HF_TOKEN=...                              # برای دانلود از HuggingFace
python tools/fetch_models.py                     # وزن‌ها + ساخت توکنایزر [fa]
python tools/fetch_datasets.py                   # دیتاست‌های ناموجود
python tools/build_dataset.py --dedupe           # ساخت MyTTSDataset/
python -m src.preprocess_ljspeech                # کش ویژگی‌ها

python train.py --max-steps 5 --batch-size 4 --no-preprocess   # smoke-test
python train.py --no-preprocess                                # اجرای کامل

python infer_fa.py --text "سلام، حال شما چطور است؟"
```

---

## چه چیزی آموزش می‌بیند

فقط **T3** — مدل زبانی‌ای که متن را به توکن‌های گفتار تبدیل می‌کند. `S3Gen` (توکن → موج صوتی) و `VoiceEncoder` فریز می‌مانند.

این برای افزودن یک زبان درست است: S3Gen یک دیکودر آکوستیک است و نمی‌داند توکن‌هایی که می‌گیرد از کدام زبان آمده‌اند. آنچه فارسی نمی‌داند، در T3 است.

```
متن فارسی
   │  نرمال‌سازی  (src/persian/normalize.py)
   │  توکنایزر    (grapheme_mtl + توکن [fa])
   ▼
  T3  ← تنها بخشی که آموزش می‌بیند (LoRA + embedding کامل)
   │
   ▼ توکن‌های گفتار (25 Hz)
 S3Gen ← فریز
   ▼
  موج صوتی 24 kHz
```

## تصمیم‌های طراحی

### مدل پایه: multilingual، نه انگلیسی

پیش‌فرض مخزن اصلی مدل انگلیسی (`t3_cfg`، vocab ۷۰۴) را برمی‌دارد و به ۲۴۵۴ resize می‌کند. آن مدل **هرگز خط عربی ندیده** — همه‌چیز باید از نو یاد گرفته شود.

ما از `t3_mtl23ls_v3` استفاده می‌کنیم: vocab‌ش از قبل ۲۴۵۴ است و روی ۲۳ زبان، از جمله عربی و عبری، آموزش دیده. شکل حروف، جهت نوشتار و بخش بزرگی از واج‌شناسی از قبل آنجاست.

> `v3` روی HuggingFace هست ولی کتابخانه‌ی رسمی هنوز `v2` را بارگذاری می‌کند. هدر safetensors هر دو را مقایسه کردیم: ۲۹۲ تنسور با shapeهای یکسان، یعنی drop-in. برای برگشتن به `v2` کافی است `t3_filename` در [src/config.py](src/config.py) عوض شود.

### توکن `[fa]`: افزودن، با مقداردهی از `[ar]`

تُکنایزر multilingual **۱۰۰٪ حروف فارسی را پوشش می‌دهد** (تست‌شده: صفر UNK روی هر ۳۲ حرف الفبا به‌علاوه‌ی آ ء ئ ؤ و نیم‌فاصله). تنها چیزی که کم بود، برچسب زبان است.

دو راه بود:

| روش | مزیت | مشکل |
|---|---|---|
| استفاده از `[ar]` | بدون تغییر vocab، پشتوانه‌ی آموزشی واقعی | فارسی و عربی فقط خط مشترک دارند نه واج‌شناسی؛ آموزش فارسی روی `[ar]` عربی را هم خراب می‌کند |
| افزودن `[fa]` | عربی دست‌نخورده می‌ماند، فارسی هویت خودش را دارد | یک ردیف بیشتر (۲۴۵۴ → ۲۴۵۵) |

`[fa]` را اضافه کردیم و embeddingش را **از روی `[ar]` کپی کردیم** نه با میانگین ۲۳ زبان. میانگین، مرکز ثقل مجموعه‌ای از زبان‌های بی‌ربط است؛ `[ar]` از قبل یعنی «خط عربی، راست‌به‌چپ» — نقطه‌ی شروع به‌مراتب نزدیک‌تری است.

### نرمال‌سازی متن فارسی

بدون این، دو رشته‌ی هم‌تلفظ به دو دنباله‌ی توکن متفاوت می‌رسند. [src/persian/normalize.py](src/persian/normalize.py):

- یکسان‌سازی املای عربی: `ي→ی`، `ك→ک`، `ة→ه`، `أ/إ/ٱ→ا`
- **نیم‌فاصله (ZWNJ) حفظ می‌شود** — واجی است (`می‌روم` در برابر `میروم`)
- **تنوین حفظ می‌شود** — در فارسی اختیاری نیست. کل پایانه‌ی قیدی `-اً` است؛ حذفش `لطفاً` را به `لطفا` تبدیل می‌کند
- کسره‌ی اضافه: `خانۀ` و `خانهٔ` هر دو به `خانه‌ی` تبدیل می‌شوند — همان چیزی که گوینده تلفظ می‌کند
- اعراب اختیاری حذف می‌شوند (متون یکدست اعراب‌گذاری نمی‌شوند)
- اعداد به حروف: `۲۵۰۰` → `دو هزار و پانصد`، `۳۶.۵` → `سی و شش ممیز پنج`؛ رشته‌های بلند (شماره تلفن) رقم‌به‌رقم

همین نرمال‌ساز داخل توکنایزر هم اجرا می‌شود، پس **زمان آموزش و زمان تولید یکسان نرمال می‌کنند**. ناهماهنگی بین این دو، شایع‌ترین دلیل مدلی است که در ارزیابی روان می‌خواند و روی ورودی واقعی به‌هم می‌ریزد.

[tests/test_persian_coverage.py](tests/test_persian_coverage.py) همه‌ی این‌ها را در برابر vocab واقعی توکنایزر بررسی می‌کند. بعد از هر به‌روزرسانی بالادست اجرایش کنید.

### چه چیزی کامل آموزش می‌بیند

LoRA روی لایه‌های توجه و MLP، ولی `text_emb` و `text_head` **کامل** آموزش می‌بینند. `[fa]` یک ردیف کاملاً جدید است و ردیف‌های حروف فارسی تا امروز فقط یاد گرفته‌اند عربی به‌نظر برسند — یک به‌روزرسانی کم‌رتبه روی آن‌ها کافی نیست.

## ماندن روی آخرین نسخه‌ی پایدار

`src/chatterbox_/` یک **آینه‌ی قابل‌تعویض** از انتشار رسمی است و هرگز دستی ویرایش نمی‌شود.

دلیلش را می‌شد در خود مخزن دید: نسخه‌ی vendor شده‌ی قبلی از یک انتشار قدیمی‌تر آمده بود و چند رفع‌باگ بالادست را نداشت — نه از روی تصمیم، بلکه چون هیچ‌کس نمی‌توانست ویرایش‌های محلی را از کد اصلی تشخیص دهد.

پس هر چیزی که لازم داریم بیرون آن زندگی می‌کند:

| فایل | چه چیزی اضافه می‌کند |
|---|---|
| [src/compat.py](src/compat.py) | hookهای آموزش، رفع dtype، بارگذاری وزن مقاوم — همه به‌صورت monkey-patch موقع import |
| [src/persian/engine.py](src/persian/engine.py) | لایه‌ی زبان فارسی |

```bash
python tools/sync_upstream.py --check     # چه چیزی جدید است
python tools/sync_upstream.py --update    # vendor آخرین پایدار
python tools/sync_upstream.py --verify    # اجرای بررسی‌های پس از همگام‌سازی
```

`--update` نسخه‌ی جدید را می‌آورد، سپس تأیید می‌کند که درخت import می‌شود، vocab هنوز ۲۴۵۴ است و پوشش فارسی سالم است. اگر هر کدام رد شود، **خودکار برمی‌گردد**.

[versions.lock.json](versions.lock.json) نسخه‌ی پکیج، revision دقیق مخزن وزن‌ها و sha256 هر فایل را نگه می‌دارد، پس هر اجرا قابل بازتولید است. `--check` نسخه‌ی جدید PyPI، جابه‌جایی revision وزن‌ها، و حتی یک `t3_mtl23ls_v4` را که هنوز به کتابخانه وصل نشده باشد گزارش می‌کند.

> **مرز کار:** فقط `src/chatterbox_/` دست‌نخوردنی است. بقیه‌ی پروژه — `train.py`، `src/config.py`، `src/preprocess_*` — مال ماست و آزادانه تغییر می‌کند.

## دیتاست

`tools/build_dataset.py` منابع را به همان چیدمان LJSpeech که [src/preprocess_ljspeech.py](src/preprocess_ljspeech.py) می‌خواند تبدیل می‌کند:

```
MyTTSDataset/metadata.csv    id|متن-خام|متن-نرمال‌شده   (بدون سطر عنوان)
MyTTSDataset/wavs/<id>.wav
```

نتیجه‌ی فعلی:

| منبع | کلیپ | ساعت | گوینده | لایسنس |
|---|---:|---:|---:|---|
| ManaTTS | ۴۴٬۳۷۹ | ۵۷.۳ | ۱ | CC0 |
| YodaLingua-Farsi | ۲۰٬۳۲۸ | ۵۷.۱ | ۶۶۱ | CC-BY-4.0 |
| PERSIAN_FARSI_NARRATION | ۳٬۳۷۸ | ۷.۱ | ~۲۰ | بررسی نشده |
| **مجموع** | **۶۸٬۰۸۵** | **۱۲۱.۴** | **۶۶۲** | |

`Persian-Farsi-Speech` (۴۶ گیگ) به‌صورت پیش‌فرض خاموش است: ۱۶ کیلوهرتز و برش‌خورده با ASR، در برابر دیکودری که ۲۴ کیلوهرتز انتظار دارد. با `--sources youtube --min-quality 3.2` می‌توان واردش کرد.

**فیلترها اختیاری نیستند.** یک جمله‌ی بدنویس‌شده یک تلفظ غلط یاد می‌دهد که تا آخر آموزش می‌ماند. هر کلیپ باید از فیلترهای مدت، طول متن، نسبت حروف فارسی و امتیاز کیفیت ادراکی (جایی که منبع دارد) رد شود. علت هر رد شدن شمرده و در `dataset_summary.json` ذخیره می‌شود.

دو صرفه‌جویی: کلیپ‌هایی که از قبل wav هستند **hardlink** می‌شوند (۴۴ هزار فایل ManaTTS صفر بایت اضافه)، و کلیپ‌های داخل parquet مستقیم از حافظه decode می‌شوند (۴۶ گیگ YouTube هرگز روی دیسک باز نمی‌شود).

## سخت‌افزار

**نتایج اندازه‌گیری‌شده** روی Quadro RTX 3000 با ۶ گیگ، LoRA r=32، fp16:

| batch | پیک VRAM |
|---|---|
| ۱ | ۲.۵۱ گیگ |
| ۴ | ۲.۸۲ گیگ |
| ۸ | ۳.۲۷ گیگ |
| ۱۶ | ۴.۰۰ گیگ |

دقت عددی **تشخیص داده می‌شود، نه فرض**. `torch.cuda.is_bf16_supported()` نسخه‌ی شبیه‌سازی‌شده را هم به‌حساب می‌آورد و روی Turing `True` برمی‌گرداند؛ آنجا آموزش درست ولی کند اجرا می‌شود، بدون هیچ خطایی. به‌جایش compute capability چک می‌شود: bf16 از Ampere (۸.۰) شروع می‌شود.

### محلی یا اجاره‌ای؟

خروجی preprocessing حدود **۵.۵ کیلوبایت به‌ازای هر کلیپ** است — ۳۷۵ مگابایت برای کل ۶۸ هزار کلیپ، در برابر ۳۰ گیگ صدای خام. پس:

**preprocessing را محلی اجرا کنید، فقط کش را آپلود کنید، آموزش را روی GPU اجاره‌ای ببرید.**


## تولید متن بلند

یک فراخوانی `generate()` سقف ۱۰۰۰ توکن گفتاری دارد و در ۲۵ هرتز یعنی حدود **۴۰ ثانیه** — و کیفیت خیلی زودتر افت می‌کند.

```bash
python infer_fa.py --text-file article.txt --long --out article.wav
```

`--long` متن را روی مرزهای واقعی جمله‌ی فارسی می‌شکند (`. ! ؟`)، جمله‌های بلندتر از حد را روی `، ؛ :` و در نهایت روی مرز کلمه — **هرگز وسط کلمه** — و همه‌ی تکه‌ها را با یک مجموعه شرایط گوینده تولید می‌کند تا صدا ثابت بماند.

یک مسئله‌ی مرتبط هم اینجا رفع شده. T3 تحلیلگر alignment خود را فقط وقتی می‌سازد که `is_multilingual` درست باشد، و آن property دقیقاً `== 2454` را می‌سنجد. افزودن `[fa]` عدد را ۲۴۵۵ می‌کند، پس آن محافظ — همان چیزی که هنگام گیر کردن یا حلقه زدن تولید، EOS را اجباری می‌کند — **بی‌صدا خاموش می‌شد**. هیچ خطایی هم نمی‌داد.

## آنچه با تست تأیید شده

- تُکنایزر: صفر UNK روی هر ۳۲ حرف الفبا، آ ء ئ ؤ، نیم‌فاصله، هر دو دستگاه عددی، و ۱۳ جمله‌ی کامل
- `[fa]` دقیقاً برابر `[ar]` مقداردهی می‌شود (فاصله‌ی صفر) و از میانگین متمایز است
- preprocessing: ۲۰۰/۲۰۰ موفق، `[fa]` در جایگاه صفر، نیم‌فاصله سالم
- آموزش: ۲۷٬۶۷۸٬۷۲۰ پارامتر آموزش‌پذیر از ۵۶۳٬۶۷۰٬۰۱۶
- تحلیلگر alignment: در هر ۴۷ گام attention واقعی می‌گیرد، صفر None، و روی بررسی long-tail فعال می‌شود
- `tools/sync_upstream.py --update` واقعاً اجرا شد؛ درخت vendor حالا بایت‌به‌بایت برابر بالادست ۰.۱.۷ است

## نکته‌های عملی

**`torchaudio.load` کار نمی‌کند** — از نسخه‌ی ۲.۹ بک‌اندهای داخلی حذف شده‌اند و به TorchCodec واگذار می‌شود. همه‌ی خواندن‌ها از `src.utils.load_audio` می‌آید که روی soundfile ساخته شده.

**`s3gen_v3.pt` دو کلید کمتر دارد** (۲۴۸۸ در برابر ۲۴۹۰): `tokenizer._mel_filters` و `tokenizer.window`، دو بافر ثابت که در `__init__` بازساخته می‌شوند. S3Gen دقیقاً همین‌ها را در `ignore_state_dict_missing` اعلام کرده ولی هیچ‌جا اعمالش نکرده. `compat.load_state_dict_tolerant` همان اعلام را — و فقط همان را — پیاده می‌کند؛ هر کلید گمشده یا اضافه‌ی دیگری همچنان خطاست.

**دانلود HuggingFace ممکن است قفل کند** — `hf_hub_download` تایم‌اوت خواندن ندارد، پس اتصالی که ساکت شود ولی بسته نشود تا ابد بلاک می‌کند (اینجا دو بار دقیقاً روی ۱ گیگ اتفاق افتاد). `tools/download.py` تایم‌اوت دارد، با Range ادامه می‌دهد، و اندازه‌ی نهایی را بررسی می‌کند.

**آداپتور به مدل پایه گره خورده** — روی `t3_mtl23ls_v3` آموزش دیده و روی `v2` یا مدل انگلیسی بارگذاری نمی‌شود. اگر پایه را عوض کردید، دوباره آموزش دهید.
